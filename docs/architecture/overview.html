DotFlow Architecture

DotFlow is a visual workflow engine on .NET 8. A Blazor WebAssembly designer builds workflow graphs, a single ASP.NET Core process stores and runs them, and each run becomes a tree of Akka.NET actors that call pluggable modules (HTTP, SQL, files, cloud storage, scripts). Persistence is swappable per store. The figures below are drawn from the code at commit 7b8011e, not from the phase docs. Markdown source of truth: 00-overview.md.

1 · System overview

Two processes, one engine, pluggable edges

Everything that executes lives in Workflow.Api: the HTTP surface, the SignalR hub, the Akka actor system, the module registry and the scripting engines. Workflow.UI only serves the WebAssembly bundle; the SPA then talks to the API directly. The blue path traces one workflow run.

  1. 1The designer (or an SDK, or a third-party webhook) calls POST /api/v1/workflows/{id}/execute. Auth runs first: API key or JWT, then a role policy such as WorkflowExecutePolicy.
  2. 2ActorWorkflowExecutionService sends CreateWorkflowInstance to the singleton WorkflowSupervisor. Webhooks take the same route through WebhookDispatcher and ActorWorkflowLauncher.
  3. 3The supervisor resolves the definition from IWorkflowRepository and spawns one WorkflowExecutor for the run. The executor hydrates variables from IVariableStore.
  4. 4The executor walks the graph with DispatchCore and spawns a child actor per ready node. Loops, parallel blocks, try/catch, transactions and streaming regions get their own supervising actor.
  5. 5A NodeExecutor looks the node's ModuleId up in IModuleRegistry, binds properties through PropertyBinder (which expands {{…}} templates), then calls ExecuteAsync.
  6. 6The module does real I/O: HTTP with Polly resilience, SQL via linq2db, S3/Azure Blob, sandboxed file access, or a JS, C# or Lua script.
  7. 7The executor records node results and status in IExecutionHistoryRepository and publishes NodeStateChanged, ProgressUpdate and similar events to the Akka EventStream.
  8. 8ExecutionEventBridge, a hosted service, subscribes to those events. It queues them on a channel, so a slow client never blocks the engine, and forwards them to hub groups.
  9. 9The SPA's RealTimeClient receives the pushes. The designer's run overlay and the Execution Monitor update live.
2 · Inside a run

Every control construct is its own actor

In the graph, control flow is just more nodes: builtin.loop.foreach, builtin.trycatch and the rest. In the engine, each of those nodes becomes a dedicated actor that owns a scoped sub-graph. That gives each construct its own timeout, cancellation token (linked to the parent's) and failure boundary.

Batch by default

A trigger produces one run that traverses the graph once. Node outputs are stored per node and port, and downstream inputs bind from them ({{input}}, {{nodeId.port}}, {{Variable.x}}). Template expansion is opt-in for each schema field, so a value that arrives from upstream can't read your secrets.

Streaming regions (Phase 5.1)

StreamRegionDetector finds maximal groups of nodes joined by stream-typed ports. It decides from the schemas alone and ignores the designer's RegionId hint. Each region runs as one Akka.Streams pipeline, and overflow spills to the configured ISpillStore. Streaming-capable modules today: CSV/JSON read and write, DB query and bulk insert, map, query, aggregate, and stream from-items/collect.

Expressions

The default IExpressionEvaluator is Jint (sandboxed JavaScript). DynamicExpresso is registered under the "csharp" key for C#-flavoured expressions. Both sit behind KeyedExpressionEvaluatorFactory. The same evaluator backs builtin.condition and builtin.loop.while. ConnectionDefinition.Condition exists in the model but the engine doesn't evaluate it yet.

3 · Module system

One schema, three consumers

A module is a .NET type that implements IWorkflowModule and publishes a ModuleSchema: ports, properties and validation rules. Built-ins register at startup. Third-party modules arrive as .wfmod packages and load into an isolated, collectible AssemblyLoadContext. Everything ends up in the same registry, and the designer, the validator and the engine all read that one schema.

5 · Persistence

Which backend can hold which store

Persistence:Provider selects sqlite, postgres, nats or composite. A composite provider assigns a backend to each of Workflows, ExecutionHistory, Variables and Blobs separately. When a provider has no webhook repository or connection registry, the API falls back to in-memory versions.

The blob store does a lot of quiet work. It holds compiled Roslyn assemblies for LINQ and transform scripts, saved script libraries, module state when Modules:StateStore=repository, and one spill-store option.

6 · Observations

Things worth knowing before changing it

Concentration

WorkflowExecutor is the center of gravity

At 3,146 lines it holds the run's state machine, persistence callbacks, scope stacks, retries and six spawn sites. DispatchCore already pulled out the routing shared with SubGraphExecutor. Scope handling and the persistence callbacks look like the next candidates to extract.

Durability

Defaults don't survive a restart

Persistence defaults to SQLite :memory:, and IExecutionStateStore is always InMemoryExecutionStateStore. Run history is durable once a real provider is configured, but pause/resume snapshots stay in memory either way.

Boundary

The UI deliberately shares no code

Workflow.UI.Client doesn't reference Workflow.Core, so a future React port stays additive. DTOs and graph logic such as StreamGraph and split preview are mirrored on the client and kept honest by drift-guard tests.

Scale-out

Single node today

ActorSystem.Create("dotflow") runs without cluster configuration, even though Akka.Cluster is referenced. Clustering (Phase 4.4) and the "streaming as a second mode" option (doc 10, sized at about 5–9 engineer-months) are the open architectural moves.

Isolation

Roslyn is quarantined

Everything that compiles user C# (Scripting.Roslyn, Database.Linq, Transform.Script) sits outside the core module assembly and is wired by the host. AddDatabaseModules() is registered separately to avoid a circular reference.

Cleanup

Leftover scaffolding

Persistence.Sql.Base contains only Class1.cs. Template Class1.cs files remain in Engine, Modules, Nats and Postgres, and Program.cs still maps /weatherforecast. The repo root also holds about 20 phase and test-fix status markdown files that could move under docs/.
